# Vazin AI Core — technical design v0.2
Status: proposed contract and relational design; no runtime code or migration. Read with ARCHITECTURE.md. First integration: HRM. GapGPT now; local VM later. No new dependency assumed.

## Source audit (branch ai-core)
- SupplyController.ProcessSupplyFactorWithAi dispatches ProcessSupplyInvoiceCommand -> ProcessSupplyInvoiceCommandHandler -> ISupplyIntegrationServices.ProcessInvoiceAsync -> SupplyIntegrationServices -> AiService.ProcessSupplyFactor -> GapgptAi.ProcessInvoiceWithGemini. Preserve SupplyResult, DTO, amount/tax/discount rules and attachment validation.
- Services/AI/GapgptAi.cs: PDF file data and image data URLs; Gemini 2.5 Flash for invoice and audio, GPT-5 Mini for summary, JSON object response, first-choice content. AiGapgptResult<T> contains Success, Data, Error, elapsed seconds. No generalized conversation/tool/usage contract evident. Live capabilities unknown.
- AiService has CRMContextDb, ViraAi, GapgptAi, date services, Issabel, logging and TaskHub dependencies. ProcessCallRecordingGemini downloads audio, stores status/results and creates report. ProcessPendingCall and older ProcessCallRecording paths use Vira and text summary; actual active callers outside reviewed worker paths remain to be traced.
- AiBackgroundService dequeues CallRecording and resolves scoped AiService; worker count 1. AiQueue is an unbounded in-memory Channel<CallRecording>. AiPendingWorker selects up to 10 WaitingForRetry calls, attempts <3, no report, every 10 seconds; updates state before enqueue. Crash window and multi-instance race require validation; not a suitable durable generic agent scheduler without redesign. Do not modify legacy path in this stage.
- Startup registers typed HttpClients and also scoped clients; inspect DI resolution and authentication in tests. Some provider credentials embedded in source; rotate and move to secret store. Provider response text can appear in error/log paths (GapgptAi.cs); sanitize before exposing externally. No secrets reproduced.
- All 5 inspected csproj target net10.0. Direct references: Framework none, Domain -> Framework, ApplicationServices -> Domain, Sql -> Domain/Framework, FrontEnd -> all 4. This is source inspection, not executed architecture checker.
- UserContextDb on baseline does not include Access Catalog DbSets. AccLevel has AccessEntity, AccessPermission, AccessRolePermission, AccessUserPermission, AccessUserScopeMember and AccessHistoryEntry. Existing catalog is a required integration dependency, not a reason to introduce parallel role-based authorization. Approved integration branch/merge later, no automatic merge to main. Until available, new AI tool routes remain disabled/deny by default.

## Contract v0.1 (proposal)
Place inward-facing ports and application DTOs in existing CRM.Core.ApplicationServices/Ai/Abstractions (or matching discovered conventions), Domain durable entities and repository interfaces under Ai; SQL implementations and configurations under Ai; concrete HTTP client adapters in existing FrontEnd Services/AI/Providers; registration in composition. No extra project, no outward reference. Existing CQRS dispatcher for new commands/queries; use established pattern. Contracts are pseudocode, not source files.

IAiProvider: ProviderKey, GetCapabilitiesAsync(ct), GenerateAsync(AiProviderRequest, ct). Optional IAiStreamingProvider only after verified capability. IAiOrchestrator: ExecuteAsync(AiTaskRequest, authorized actor context, ct). User-facing module contract accepts TaskKey, validated input, optional conversation ID and cancellation; no arbitrary provider/model URL or trust of client actor/classification. Internal service derives ActorId, permissions, current Scope, DataClass and allowed route. AiProviderRequest is normalized: RequestId, ModelKey, ordered messages with role/text and approved attachment reference, optional JSON schema, tool schemas, output limit and deadline. Resolve attachment bytes only after authorization and size/type policy. No provider-specific JSON in callers.
AiProviderResult: status (Succeeded, Unavailable, RateLimited, Timeout, InvalidResponse, Unsupported, Rejected, Cancelled, ConfigurationError), text/structured content, typed tool requests (call ID, tool key, arguments), finish reason, usage (nullable input/output/total), provider/model, safe error code, correlation ID. Cancellation propagated; no retries after externally visible partial response or non-idempotent action. No success on missing required content. Validate output against schema before applying; unknown usage is null, not zero. Max tool iterations, output limits and timeouts enforced server-side.
Capability flags: Text, StructuredJson, Image, Pdf, AudioInput, ToolCalling, Streaming, UsageReporting, Embeddings. Each provider/model capability has evidence and last verified timestamp; unknown != supported. Existing code proves request format only, not live support. Adapter test with synthetic fixtures. VM protocol/URL/auth/model runtime and GPU capacity are open.
Task route keys initial: Assistant.Chat, Supply.InvoiceExtract, Calls.AudioAnalyze, Calls.TextSummary, Hr.AttendanceSummary, Hr.PolicyQuestion. Preserve legacy routing until regression tests. Hr tasks default LocalOnly if identifiable; while VM unavailable only approved de-identified/aggregated data or synthetic test inputs can use GapGPT. No fallback for LocalOnly; cloud fallback explicit per task and data class. No automatic secret transfer, conversation migration or external endpoint chosen by model. Endpoint allowlist, TLS validation, size/time/rate caps. Vira speech remains separate specialized port, not generalized LLM.

## Proposed relational model (SQL Server)
Business PKs uniqueidentifier matching BaseEntity Guid where appropriate; Identity IDs nvarchar(450) strings, validated against UserContextDb; no EF navigation/cross-context FK assumed. UTC datetime2 or datetimeoffset for instants, rowversion for mutable configuration; bounded nvarchar keys, decimal(19,6) costs, bigint usage. Names/types below are candidates; no physical schema approved.
| Entity | Fields (besides Id/audit) | Constraints / links |
|---|---|---|
| AiProvider | Key(64), DisplayName(128), Kind, EndpointRef, SecretRef, IsEnabled | unique Key; endpoint/secret references not raw key; admin-only |
| AiModel | ProviderId, ModelKey(128), DisplayName, CapabilityMask, VerificationStatus, VerifiedAtUtc, Enabled | unique ProviderId+ModelKey; FK Provider |
| AiTaskRoute | TaskKey(96), PrimaryModelId, FallbackModelId?, AllowedDataClass, TimeoutMs, MaxOutputTokens, Enabled, RowVersion | unique TaskKey+DataClass; reject invalid fallback |
| AiPrompt | Key(96), ActiveVersionId?, Enabled | unique Key |
| AiPromptVersion | PromptId, VersionNo, Template, Status, PublishedAtUtc?, PublishedBy | unique PromptId+VersionNo; immutable published versions; active version belongs to same prompt |
| AiToolDefinition | ToolKey(96), PermissionKey, Risk, InputSchemaVersion, Enabled | unique ToolKey; maps to registered code only |
| AiConversation | OwnerUserId, Title(200), Status, UpdatedAtUtc, RetainUntilUtc? | owner/time index; restricted access |
| AiMessage | ConversationId, SequenceNo, Role, Content, Status, CreatedAtUtc, Classification | unique ConversationId+SequenceNo; retention and encryption policy |
| AiRequest | TaskKey, ModelId, PromptVersionId?, ConversationId?, ActorId, CorrelationId, Status, StartedAtUtc, FinishedAtUtc?, ErrorCode | correlation unique; metadata only by default; FK optional conversation |
| AiToolExecution | RequestId, ToolKey, ActorId, Status, ArgumentHash, ApprovalId?, IdempotencyKey, StartedAtUtc, CompletedAtUtc? | unique IdempotencyKey; no sensitive raw args in audit |
| AiActionApproval | ActorId, ToolKey, ArgumentHash, ExpiresAtUtc, Status, ConsumedAtUtc?, RowVersion | one-time preview bound to actor and payload |
| AiUsageRecord | RequestId, InputTokens?, OutputTokens?, TotalTokens?, Cost?, Currency?, RateVersion? | unique RequestId or per-attempt key when retries metered; unknown null |
| AiAgent / AiAgentSchedule / AiAgentRun | Key, ServiceIdentityRef, TaskKey; schedule timezone/cadence; run scheduled instant, attempt, status | unique agent+trigger/run key; no implicit superuser |
| AiFinding | AgentRunId?, DedupKey, Severity, SubjectRef, Status, AssigneeId?, ResolvedAtUtc? | unique active finding per dedup key; subject access rechecked |
Later: AiKnowledgeDocument/version/chunk/ACL; AiMemory (opt-in, owner, expiry), AiFeedback. Define document ACL at retrieval; no unscoped vectors. Implement first vertical slice with minimum tables only; avoid speculative schema. Audit UTC independent of legacy BaseEntity local date defaults; preserve root conventions and document any deviations. Restrict deletes of published versions and audit; conversation retention/deletion separately governed.

## Security and acceptance
Permission proposal: Ai.Assistant.View/Use, Ai.Conversation.Own, Ai.Provider.Manage, Ai.Prompt.Manage, Ai.Tool.Manage/Execute, Ai.Agent.Manage, Ai.Finding.View, Ai.Usage.View, Ai.Audit.View; actual codes mapped to AccLevel after approved integration. Every underlying module permission/scope also applies. No access granted by these docs. Background identity explicit, scope revoked before next action. Model cannot authorize actions.
Test cases: mock text success/invalid JSON/empty content/429/timeout/cancel, unsupported tool and streaming, local-only route never hits cloud, scope isolation and revoke, untrusted prompt injection, invalid tool input, idempotent confirmation, old invoice/audio results and no new direct DbContext in application. Run actual build/checker before operational changes are approved. No live API test, runtime code, migrations or architecture checker executed in this stage.

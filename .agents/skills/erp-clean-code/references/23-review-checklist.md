# 23. Review checklist

**Classification:** Mandatory

## Required behavior
Use before-development, after-development, code-review, security-review, database-review and refactoring-review checklists where relevant. Report findings by severity, path, scenario, impact and correction. Mark N/A with rationale; separate documented policy from operational compliance.

## Prohibited behavior and exceptions
Do not tick unfinished checks, report speculative defects as verified, or modify during review-only tasks.

## Examples
Good: mark build not run and why; bad: claim all 33 sections enforced from file presence.

## Review checklist
- [ ] Review evidence and update RULES-CHECKLIST.md when governance implementation changes.
- [ ] Record relevant evidence and justified deviations; do not claim an unexecuted check.

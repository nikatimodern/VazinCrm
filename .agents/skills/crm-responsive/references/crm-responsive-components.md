# Responsive components

Inspect the actual component and its scripts first. These are decisions for affected components, not claims that every page uses every pattern. Preserve data, authorization, validation, sorting, filtering, paging, submission, and navigation behavior while changing presentation.

| Component | Mobile | Tablet | Laptop and desktop | Failure checks and behavior to preserve |
| --- | --- | --- | --- | --- |
| DataTables and tables | Give dense columns an intentional local scroll area or a task-specific compact presentation. Keep row actions reachable. | Fit priority columns; scroll only the table region if needed. | Use available width and readable columns. | Check header/body alignment, paging/search controls, action menus, and redraws. Preserve DataTables sorting, filtering, paging, and row identity; do not assume card conversion is always appropriate. |
| Forms and inputs | Stack fields and actions; keep labels and errors visible above the mobile keyboard. | Group related fields only when they fit. | Use bounded form width and sensible columns. | Check long Persian labels, validation, focus, and submit state. Preserve field names and server validation. |
| Bootstrap modals and SweetAlert2 | Fit viewport height, scroll content, keep close/confirm actions reachable. | Use available width without clipping. | Keep readable maximum width and focus order. | Check nested scroll, backdrop, keyboard, reopen, and TomSelect layering. Preserve confirm/cancel meaning and modal lifecycle. |
| Cards and grids | One readable track, unless content supports more. | Add columns where cards remain legible. | Grow tracks without excessive line length. | Check uneven card height, wrapping, and action visibility. Preserve card links and states. |
| Dashboard and charts | Stack panels; keep chart labels/legends legible and provide local overflow if intrinsically wide. | Increase panel columns cautiously. | Use available grid space. | Check canvas resize and data labels. Preserve chart data, filters, and interactions. |
| Sidebar and mobile menu | Keep `#mobileMenuBottom` and `#mobileDrawer` usable, with content clear of the bar. | Verify actual sidebar/menu transition and available content width. | Keep `#desktopSidebar` and `#mainWrapper` aligned. | Check overlay, safe area, scroll lock, collapsed state, and active link. Preserve permission-filtered menu items and destinations. |
| Navigation and tabs | Permit local tab scrolling or wrapping with visible active state. | Show more tabs if space allows. | Keep clear hierarchy and keyboard focus. | Check clipped labels and hidden actions. Preserve tab selection and routes. |
| Kanban and drag/drop | If the affected board uses `Sortable`, allow board-level horizontal scrolling and reachable columns. | Fit more columns where possible. | Show columns without tiny cards. | Check drag handles, touch scrolling, drop targets, and status updates. Preserve order and move semantics; inspect actual board before applying. |
| TomSelect and dropdowns | Fit control and popup within viewport; avoid keyboard or modal clipping. | Keep popup aligned with trigger. | Use available form width. | Check portal/parent, scroll, focus, and repeated initialization. Preserve selected values and search behavior. |
| Buttons and action menus | Wrap or group actions; keep touch targets and menu panels reachable. | Fit actions without crowding. | Keep actions near their content. | Check overlap, disabled/loading states, and click targets. Preserve action intent and permissions. |
| Report pages | Stack filters; scroll wide results locally and keep export actions reachable. | Reflow filters and result area. | Use readable filter/results grid. | Check date/select popups, table controls, long values, and exports. Preserve filters, query parameters, and result meaning. |

Existing examples include DataTables in `wwwroot/js/report.js` and other feature scripts, TomSelect in report and deal scripts, Sortable in `wwwroot/js/deal/deal.js`, charts in dashboard scripts, and shared menu markup in `Views/Shared/Menu/_Menu.cshtml`. Verify current usage and loaded styles before acting.

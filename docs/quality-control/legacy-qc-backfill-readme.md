# انتقال کنترل کیفیت قدیمی سفارش‌ها به اقلام فاکتور

این بک‌فیل به صورت **مایگریشن داده‌ای** با شناسه
`20261119190000_BackfillLegacyQualityControlItems` ثبت شده است.

## نگاشت اطلاعات

- رکورد قدیمی `QualityControls` به یک `DealId` تعلق دارد؛ رکورد جدید `QualityControlItemReviews` به `FactorItemId` تعلق دارد.
- برای هر Deal دارای کنترل کیفیت قدیمی تکمیل‌شده، همه اقلام **تمام فاکتورهای تایید‌شده و غیرمرجوعی** همان Deal که در صف کنترل کیفیت فعلی واجد شرایط هستند انتخاب می‌شوند (Deal تایید مالی شده باشد).
- هر قلم بدون رکورد کنترل کیفیت جدید، با `Status = 1` (بدون مغایرت) ثبت می‌شود؛ حتی اگر نتیجه قدیمی Deal دارای مغایرت بوده باشد. دلیل: در اطلاعات قدیمی، قلم مرتبط با مغایرت مشخص نیست. **مغایرت تاریخی در رکورد اصلی حفظ می‌شود** و در `CommentText` هر قلمِ منتقل‌شده نیز ثبت می‌شود.
- `Status = 1` یا `2` قدیمی نشانه بررسی تکمیل‌شده است. برای `Status = NULL` تنها وقتی حداقل یک پاسخ ذخیره‌شده داشته باشد، رکورد تکمیل‌شده محسوب می‌شود؛ وجود پاسخ `1` نشان‌دهنده مغایرت قدیمی است.
- وضعیت‌های قدیمی `4` (عدم پاسخ) و `5` (شماره نامعتبر) و موارد بدون پاسخ پرسش‌ها، به بررسی اقلام تبدیل نمی‌شوند.
- رکورد کنترل کیفیت جدیدِ موجود، حتی اگر نرم‌حذف شده باشد، **تغییر یا جایگزین نمی‌شود**. بک‌فیل تکرارپذیر است.
- اطلاعات زمان ثبت و کاربر ثبت‌کننده از کنترل کیفیت قدیمی حفظ می‌شود. پاسخ‌های قدیمی سؤال‌ها به قلم خاصی نسبت داده نمی‌شوند.

## قبل از اجرا

1. ابتدا از دیتابیس CRM بک‌آپ بگیرید.
2. فایل `docs/quality-control/legacy-qc-backfill-preview.sql` را در همان دیتابیس اجرا کنید. این فایل فقط گزارش می‌دهد و داده‌ای را تغییر نمی‌دهد.
3. ستون‌های `WouldInsert` و `NewItemsFromDiscrepantLegacyDeals` را بررسی کنید. اگر آمار با انتظار شما سازگار نیست، مایگریشن را اجرا نکنید.

## اجرا در محیط پروژه

پس از Pull کردن برنچ `qc`، از ریشه پروژه و در محیطی که به دیتابیس مقصد متصل است دستور زیر را اجرا کنید:

```powershell
dotnet ef database update 20261119190000_BackfillLegacyQualityControlItems --context CRMContextDb --project "02.Infrastructures/CRM.Infrastructures.Sql/Generics.Infrastructures.Sql/CRM.Infrastructures.Sql.csproj" --startup-project "03.EndPoints/CRM.EndPoint.FrontEnd/CRM.EndPoint.FrontEnd.csproj"
```

**این مایگریشن فقط یک بار توسط EF Core اعمال می‌شود و در تراکنش مایگریشن اجرا می‌شود.**
اجرای دوباره SQL نیز نباید بررسی‌های قبلاً ثبت‌شده را تغییر دهد؛ برای جلوگیری از ایجاد رکورد تکراری بررسی وجود رکورد و قفل روی کلید انجام می‌شود.

## پس از اجرا

همان اسکریپت preview را دوباره اجرا کنید:
- برای تمام سفارش‌های واجد شرایط منتقل‌شده، `PendingInsertions` باید صفر باشد.
- `PreservedItemReviews` تعداد رکوردهای موجود را نشان می‌دهد.
- کنترل کیفیت یک مشتری را از UI باز کنید و نتیجه تمام اقلام مربوط به فاکتورهای واجد شرایط را بررسی کنید.

**توجه:** این انتقال داده‌ای برگشت خودکارِ حذف‌کننده ندارد. در متد `Down` رکوردهای منتقل‌شده حذف نمی‌شوند؛ زیرا ممکن است کاربر پس از اجرا آن‌ها را ویرایش کرده باشد.

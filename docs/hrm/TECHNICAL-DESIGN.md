## Design decisions
EmployeeProfile is HR identity, optional link to existing account, not a replacement for AppUser. One profile per linked account; employees without a login are supported. First/last name authoritative source for HR profile must be agreed: initialize from verified account with explicit link, then controlled HR edits; do not silently overwrite account details. Reuse PersonId only if actual person/customer relationship is confirmed; do not conflate customer record and employee. BaseAdmin position is legacy operational position; map to JobPosition only via reviewed mapping, no destructive conversion. Account access/termination changes need approved separate Identity command, not an automatic side effect. Organization hierarchy and employment history are effective-dated. Import preview + manual review for employee code and duplicate matches. No auto-link by name or mobile alone.

## Schema proposal (SQL Server)
Use Guid PK for HR business entities; Identity references string nvarchar(450), application validates via UserContextDb; store HR data in CRMContextDb by proposal. No assumed cross-context EF FK. Within HR use explicit FKs, restricted deletes, unique filtered indexes and rowversion for mutable aggregates. Use date for local work date, datetimeoffset or UTC datetime2 for instants, explicit timezone identifier and source offset, time(0) or integer minute offset for shifts, bigint/minute totals where justified, decimal(19,4) for monetary candidate pending finance scale and unit approval. All lengths below are proposals, no migrations.

## Attendance ingestion and processing
Device adapter port proposed: GetInfoAsync, ReadEventsAsync(cursor,pageSize,ct) returning events, nextCursor, hasMore; GetHealthAsync. Support push adapter only if verified protocol requires it. Device identity authenticated and network limited; read-only no clock changes, delete or enrollment. Sync worker lease per device/stream; request external batch outside DB transaction, validate and normalize, transactionally persist accepted/quarantined events and new cursor, then report status. Retry bounded with exponential backoff, replay safely after outage. When device sequence resets, use verified device epoch/session or manual reconciliation. Never dedup solely employee+minute; preserve distinct legitimate events. No silent assignment of unknown employee, timezone or direction. Keep unknown source timezone quarantined; use confirmed IANA/Windows mapping, source offset and DST ambiguity rules; Persian display does not change stored time.
Compute day/overnight work windows using effective shift/calendar and rule version; sort normalized events, pair according to verified direction/policy, flag missing or ambiguous punches instead of inventing exit. Apply only approved corrections/leave/mission/overtime. Persist result revisions and input provenance; deterministic rerun, monthly approval and lock. Closed-period late punches produce review case, no automatic overwrite. Actual company work policies required before coding rules. AI consumes only approved authorized aggregates/explanations, never calculates payable hours or changes payroll.
